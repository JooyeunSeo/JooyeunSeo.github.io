## Claude Code

🧠 **언어 모델(LLM):** 두뇌 (생각하고 계획을 세우지만 손이 없어서 파일 읽기나 명령 실행은 불가능)    
🦾 **도구(Tool):** 도구 상자 (파일 읽기, 명령 실행 등 실제 기능 담당)     
🤖 **코딩 어시스턴트(System):** 두뇌와 도구를 연결해 주는 몸체

### Coding Assistant

- 코딩 어시스턴트는 `언어 모델 + 도구(tool)`를 이용해 문제를 해결하는 시스템
- 동작 과정:
   1. 코드/에러 등 문맥 파악
   2. 문제 해결 계획 수립
   3. 파일 편집 및 명령을 실제로 실행
- `Tool Use` 과정
   1. 사용자: "main.go 파일에 어떤 코드가 있어?" 라고 질문
   2. 어시스턴트: 언어 모델에게 "ReadFile: 파일명"으로 답변하도록 지침(tool instructions)을 첨부  
   3. 언어 모델: 코딩 어시스턴트에게 "ReadFile: main.go"으로 답변하여 도구 사용을 요청
   4. 어시스턴트: 실제 컴퓨터 하드디스크에서 파일을 읽어 언어 모델에 전달
   5. 언어 모델: 읽어온 파일 내용을 바탕으로 사용자에게 최종 답변
- Claude 계열 모델이 코딩에 강한 이유 → 뛰어난 도구 사용 성능
   - 복잡한 문제 해결: 여러 도구를 조합해서 어려운 버그도 스스로 해결
   - 확장성: 새로운 도구(기능)를 추가해도 금방 배워서 사용
   - 강력한 보안: 파일 전체를 서버로 업로드하지 않고 필요한 부분만 도구로 작업하기 때문에 훨씬 안전

### Tools with Claude Code

> Claude 코드에서 사용 가능한 기본 도구들을 조합하여 복잡한 작업을 완료할 수 있다.     
<a href="https://code.claude.com/docs/en/tools-reference" target="_blank">Tools reference 참조</a>

예1. 자바스크립트 'chalk' 라이브러리의 성능 문제를 찾아서 최적화하도록 요청
1. Run Benchmarks: 현재 속도를 측정
2. Write a sample file to explore the worst case: 최악의 상황을 재현하는 파일(테스트 케이스)을 작성
3. Use a CPU Profiler and analyze the results: 어떤 줄에서 CPU에 가장 많은 부하가 걸리는지 분석
4. Implement improvements: 비효율적인 함수를 더 빠른 로직으로 교체
5. Verify improvements: 1번의 벤치마크를 다시 실행하여 속도가 얼마나 줄었는지, 부작용은 없는지 확인 후 마무리

---

예2. 비디오 스트리밍 플랫폼 유저들의 데이터 세트(CSV 파일) 분석 및 인사이트 요청
1. Write code in a notebook to examine the data format: CSV 파일 위치 확인 후 노트북 파일에 코드 작성
2. Run the code and examine the results: 노트북 실행 후 출력된 결과를 읽어서 결측치 및 이상한 값 체크
3. Add cells, executing each to guide its analysis: 최종 결론이 나올 때까지 아래 과정을 반복
   1. 가설("최근 한 달간 시청 시간이 적은 유저의 이탈률이 높다" 등) 설정
   2. 관련 그래프를 그리는 등의 코드를 추가
   3. 실행
4. Write a final summary: 지금까지 분석한 모든 결과를 종합하여 텍스트로 정리

예3. 채팅 앱의 UI 스타일 변경      
(`Playwright MCP Server`로 Claude 코드에 브라우저 액세스 권한을 부여)
1. Open browser: 컴퓨터 내부에서 가상의 브라우저를 실행
2. Navigate to the app: 브라우저 주소창에 앱의 주소를 입력하여 접속
3. Take a screenshot: 현재 화면을 사진으로 찍어서 이미지 데이터를 분석
4. Update styling: 분석한 내용을 바탕으로 실제 CSS 파일이나 React 컴포넌트 파일을 열고 디자인 변경
